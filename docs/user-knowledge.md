## 2026-08-14 — 大規模なMO2環境での更新確認

### 出典コンテキスト

- 出典：ユーザーが提供した7DTDとMO2に関する会話画像です。
- 出典日時：不明です。
- 会話の参加者：ModScope作者と匿名化した外部MO2ユーザーです。
- 記録日：2026-08-14です。

### 直接報告

#### ModScope作者の観察

- MODページの確認では、ローカルのMOD一覧、フォルダー、Nexus、メモを行き来する負担があります。
- ModScopeは、ブラウザーとローカルMOD一覧を組み合わせて、この確認負担を減らす目的で作られています。
- ModScope作者は、高信頼のインストール済みバージョンと最新バージョンの比較が有用かを質問しました。

#### 外部MO2ユーザーの報告

- 外部MO2ユーザーは、約500 MODのMODリストをMO2で管理、配布していると報告しました。
- 外部MO2ユーザーは、更新状況をNexusで手動追跡していると報告しました。
- 外部MO2ユーザーは、更新時にバージョン判定が誤る場合があると報告しました。
- 外部MO2ユーザーは、標準状態では依存関係を把握できないと報告しました。
- 外部MO2ユーザーは、ダウンロード時にrequirementsを手動確認していると報告しました。
- 外部MO2ユーザーは、MODの実行自体はvanilla Load Orderで問題ないと報告しました。
- 外部MO2ユーザーは、ゲームのMOD読込規則を理解していればトラブルシュートしやすいと報告しました。

### 製品上の示唆

- インストール済みバージョンとWeb上の最新バージョンを高い確度で比較する機能を候補とします。
- バージョン比較は、インストール側の値、Web側の値、取得時点、根拠、未確認事項を分けて表示します。
- MODの依存関係とrequirementsを確認する機能を候補とします。
- 依存関係が確認できない場合は、推測せずunknownとして表示します。
- MO2のvanilla Load Orderとsource of truthを置き換えない設計を維持します。
- MO2環境の認識、比較、診断を補助する方向とします。

### ユーザー検証済み需要

- `Validated demand: high-confidence version check + requirement check + compatibility check`
- 高信頼のバージョンチェック、requirementsチェック、互換性チェックは、ユーザーが有用な需要として明示的に検証しました。
- 需要の検証は、データソース、判定規則、UI、実装方式の確定を意味しません。

### 仮説

- 更新確認の失敗は、MODページのversion metadata、更新日時、または自動判定規則に関係する可能性があります。
- 互換性チェックの対象範囲と判定根拠は、追加確認が必要です。

### 未確認事項

- 画像内の会話だけでは、高信頼のバージョン比較が実際に有用かどうかは確認できませんでした。後続のユーザー明示により、需要は検証済みとして記録します。
- バージョン判定が誤る具体的な条件は確認できていません。
- 必要な依存関係の種類、optional dependency、推奨MOD、load order要求の優先度は確認できていません。
- 互換性チェックで扱うゲームバージョン、MOD間の競合、load order、依存関係の範囲は確認できていません。
- 「プラグインで対応できる可能性がある」という発言は、実装仕様として確認していません。
- この報告が他のMO2ユーザーにも当てはまるかは確認していません。

### 記録上の判断

- 約500 MODをMO2で運用できることは、匿名化した1名の外部ユーザー報告です。
- Nexusによる手動更新確認とrequirementsの手動確認は、外部ユーザーの運用上の知見です。
- 高信頼バージョンチェック、requirementsチェック、互換性チェックは、ユーザーが明示した検証済み需要です。
- Prior-artとEvidence Modelの設計判断は、research note `docs/research/prior-art-evidence-model.md`へ分離して記録します。
- この記録から、各チェックの具体的な実装要件を確定しません。
